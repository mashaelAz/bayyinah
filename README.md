# تثبّت — قبل أن تنشر… تثبّت

منصة ذكية تساعد المستخدم على التحقق من الأحاديث والعبارات الدينية المتداولة قبل نشرها. يرفع المستخدم صورة البطاقة أو يلصق النص، فتقرأ المنصة العبارة وتفصلها عن الإضافات الدعوية، وتبحث عنها في الموسوعة الحديثية بالدرر السنية، ثم تعرض النص الأقرب وحكم المحدّث ومصدره، والفروق بين النص المتداول والأصل.

> **الذكاء الاصطناعي يحدد ويبحث ويطابق، والمصدر العلمي الموثوق هو الذي يزوّد النظام بالحكم.**

مشروع مقدّم إلى «تحدي الذكاء الاصطناعي في خدمة المحتوى الإسلامي» 2026 — مسار أدوات المعرفة والتحقق.

---

## ما الذي يعمل

- رفع صورة (PNG/JPG/JPEG/WEBP) وقراءتها بالعربية داخل المتصفح (Tesseract.js)، مع نص مستخرج قابل للتصحيح قبل البحث.
- لصق النص مباشرة، مع ثلاثة أمثلة جاهزة.
- فصل صيغة النسبة («قال رسول الله ﷺ») والعبارات الدعوية («انشر تؤجر»، «لا تجعلها تقف عندك»...) عن المتن، وعرضها بشفافية دون حذفها من الأصل.
- تصنيف نوع النص (حديث محتمل، آية، دعاء، أثر، قول، غير معروف) دون نسبة أي نص إلى النبي ﷺ بلا نسبة صريحة.
- اتصال مباشر من الخادم بالموسوعة الحديثية في الدرر السنية، مع نسخة مخزنة موثقة بديلًا عند تعذر الاتصال.
- محرك مطابقة بأربعة مستويات: حرفي، بعد التطبيع، عبارة، تقريبي.
- خمس حالات للنتيجة: مطابقة موثقة، اختلاف في اللفظ، لم نعثر، يحتاج إلى تثبّت، تعذر المصدر.
- «بصمة النص»: محاذاة كلمة بكلمة تُبرز ما أُضيف إلى النص المتداول وما سقط منه.
- عرض حكم المحدّث حرفيًا مع الراوي والمحدّث والمصدر والرقم ورابط المصدر، وجدول بأحكام المحدثين على الروايات المطابقة.
- مسار الدليل «كيف وصلنا لهذه النتيجة؟» لكل عملية.
- مشاركة النتيجة برابط ورمز QR، وسجل محلي لعمليات التحقق دون حسابات.
- مساعد لغوي اختياري (Claude) لفصل المتن فقط، بحماية تمنعه من إضافة أي لفظ غير موجود في النص المدخل.

## قواعد غير قابلة للتفاوض في الكود

- لا توجد دالة تحكم على الحديث. الدوال المستخدمة: `searchHadithSources()`، `matchHadithText()`، `extractSourceGrade()`، `explainResult()`.
- أي حكم يُعرض يأتي من حقل `grade` في سجل المصدر، منقولًا حرفيًا.
- `similarity` درجة تشابه نصي فقط، ومكتوب ذلك في الكود والواجهة.
- «لم نعثر» لا تُكتب «موضوع» أبدًا. وإذا تعذر المصدر المباشر ولم تجد النسخة المخزنة تطابقًا، تُعرض «تعذر الوصول إلى المصدر» بدل «لم نعثر».

## التشغيل محليًا

المتطلبات: Node.js 22.6 أو أحدث.

```bash
npm install
cp .env.example .env.local
npm run dev        # http://localhost:3000
npm test           # اختبارات محرك التحقق
npm run build && npm start
```

### متغيرات البيئة

| المتغير | القيمة الافتراضية | الوظيفة |
|---|---|---|
| `HADITH_PROVIDER` | `auto` | `auto` الدرر مباشرة مع بديل مخزن، `dorar` مباشر فقط، `demo` المخزن فقط |
| `DORAR_API_URL` | `https://dorar.net/dorar_api.json` | رابط الخدمة العامة للموسوعة الحديثية |
| `DORAR_API_KEY` | فارغ | محجوز لمفتاح رسمي إن صدر؛ غير مستخدم حاليًا |
| `ANTHROPIC_API_KEY` | فارغ | اختياري: يفعّل المساعد اللغوي لفصل المتن |
| `AI_MODEL` | `claude-haiku-4-5-20251001` | النموذج المستخدم للمساعد |

بدون أي مفتاح، يعمل المشروع كاملًا بالقواعد اللغوية والاتصال المباشر بالدرر السنية.

## النشر (رابط Live Demo)

**Vercel (موصى به لمشاريع Next.js):** ارفع المستودع إلى GitHub، ثم استورده من vercel.com/new، وأضف متغيرات البيئة، ثم Deploy. لا يحتاج إعدادًا إضافيًا.

**Netlify:** استورد المستودع، وأمر البناء `npm run build`، وNetlify يتعرّف على Next.js تلقائيًا.

**Render:** خدمة Web Service، أمر البناء `npm install && npm run build`، وأمر التشغيل `npm start`. تنبيه: الخطة المجانية تتوقف عند الخمول، فافتح الرابط قبل التحكيم بدقائق.

بعد النشر: افتح `/api/health` للتأكد من التشغيل، ثم جرّب الأمثلة الثلاثة.

## البنية

```
المستخدم
  ↓ صورة أو نص
lib/ocr/ocrService.ts        قراءة الصورة (داخل المتصفح)
  ↓
lib/arabic/normalize.ts      تطبيع للبحث فقط (الأصل لا يُعدّل)
lib/arabic/extract.ts        فصل النسبة والإضافات + تصنيف النص
lib/ai/assist.ts             (اختياري) مساعد لغوي للفصل فقط
  ↓
lib/providers/               HadithProvider: DorarProvider | DemoProvider
  ↓
lib/matching/engine.ts       مطابقة بأربعة مستويات
lib/matching/diff.ts         بصمة النص
  ↓
lib/verify.ts                الحالة + الدليل + الشرح
  ↓
components/ResultCard.tsx    بطاقة النتيجة
```

استبدال المزوّد لا يغيّر الواجهة: أي مصدر جديد يطبّق واجهة `HadithProvider` في `lib/providers/types.ts`.
